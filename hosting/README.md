# Обновление копии сайта на SpaceWeb

Исходники сайта по-прежнему находятся в `site/` публичного GitHub-репозитория.
GitVerse сохранён как резерв. Тексты, дизайн и режим согласования при переносе не меняются.

2 ноября 2026 года технический перенос проверен: основной адрес `https://serafima-demina.com/`, сертификат установлен для домена и `www`. Правила ниже уже применены в `public_html/.htaccess`. HTTP и `www` перенаправляются кодом 301 на основной HTTPS-адрес, пути и параметры сохраняются. Все 22 публичных файла совпали с main по Git blob-хешам и SHA-256. Меню, контакты, аккордеоны, слайдер, увеличение и закрытие галереи проверены в браузере компьютера. На реальных телефонах в этом цикле не проверялось; файлы сайта и адаптивные стили не менялись.

## Установленные файлы

- `/home/d/demserafim/public_html/` — содержимое `site/`.
- `/home/d/demserafim/serafima_sync.py` — копия этого служебного скрипта вне публичной папки.
- `/home/d/demserafim/.serafima-publisher/state.json` — последний опубликованный коммит и SHA-256 файлов.
- `/home/d/demserafim/site-sync.log` — отчёт обновлений и ошибки. Не публиковать его на сайте.

Cron выполняет команду каждые 10 минут (`*/10 * * * *`):

```sh
python3.11 /home/d/demserafim/serafima_sync.py --home /home/d/demserafim >> /home/d/demserafim/site-sync.log 2>&1
```

У сервера старый интерпретатор с именем `python3`; необходим явный `python3.11`.
Скрипт не требует ключей, токенов или новых пакетов. Он использует публичный GitHub API.
При недоступности GitHub, ограничении запросов или несовпадении хеша загрузка останавливается до замены файлов.
Параллельный запуск блокируется файловым замком. Проверенные файлы заменяются по одному атомарно, `index.html` последним.
Файлы вне манифеста не удаляются. Не добавлять на этот аккаунт второй сайт в тот же каталог.

## Изменения и проверка

После изменения `site/` сохранить коммит в `main`. Дождаться очередного Cron и строки `Published <commit>: ... verified files`, затем проверить HTTPS и SHA-256 публичных файлов. Строка `Current <commit>` означает, что коммит и локальные хеши совпадают.
Проверка GitVerse `Verify public website` по-прежнему требуется для правок `site/`.
Для восстановления содержания отменить ошибочный коммит обычным `git revert`, сохранив новые изменения других редакторов, и проверить следующую публикацию.

Изменения `hosting/serafima_sync.py` автоматически не исполняются: агент отдельно загружает проверенную версию в домашний каталог через файловый менеджер SpaceWeb.
Не класть служебный скрипт, журнал или файлы авторизации в `public_html`.

## HTTPS

Сертификат выпускается через SSL → Установить → Let's Encrypt, с подтверждением DNS SpaceWeb. Для адреса с `www` нужен охват поддомена. Выпуск и установку обязательно проверять по фактической доступности HTTPS обоих адресов.
Только после этой проверки скопировать `spaceweb.htaccess` в `public_html/.htaccess`, предварительно сохранив существующие правила, если они есть. На момент подготовки существующий файл пуст.
Конфигурация перенаправляет HTTP и `www` на `https://serafima-demina.com/`, сохраняя путь и параметры. Она остаётся настройкой SpaceWeb и не передаётся в GitVerse.
После применения проверить отсутствие циклов и точные хеши всех публичных файлов по HTTPS.

Снятие надписи «Версия для согласования» и `noindex` выполняется только по отдельному поручению владельца после проверки содержания.
