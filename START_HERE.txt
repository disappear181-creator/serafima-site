ОДИН РАЗ: ДОСТУП СЕРАФИМЫ
1. Серафима создаёт собственный бесплатный аккаунт GitHub, если его нет.
2. Антон открывает репозиторий → Settings → Collaborators → Add people,
   выбирает точный логин Серафимы и отправляет приглашение.
3. Серафима принимает приглашение в письме GitHub.
   В личном репозитории collaborator получает возможность писать изменения.
4. Серафима входит в свой ChatGPT на компьютере и открывает
   Customize / Настроить → Plugins / Плагины (https://chatgpt.com/plugins).
   Находит GitHub → устанавливает/подключает → авторизует СВОЙ GitHub.
   Подключение должно предоставлять доступ к disappear181-creator/serafima-site.
   Создаёт чат в режиме Work / Работа и выбирает @GitHub.
   Work и Codex входят в Plus; доступ конкретного подключения подтверждается
   только успешной проверкой в её аккаунте.

ЕСЛИ РЕПОЗИТОРИЙ НЕ ВИДЕН
Принятое приглашение и доступ приложения — отдельные вещи.
Антон проверяет на СВОЁМ GitHub: аватар → Settings → Applications →
Installed GitHub Apps → приложение, использованное подключением →
Configure → Repository access. Там должен быть разрешён serafima-site.
Не подключайте приложение под аккаунтом Антона в GPT Серафимы.
При непонятном экране покажите его; не передавайте пароли и токены в чат.

ПЕРВОЕ СООБЩЕНИЕ В GPT СЕРАФИМЫ

Не считай подключение проверенным лишь потому, что удалось прочитать код.

ПОСЛЕ ПРОВЕРКИ
Прикрепляйте скриншоты и описывайте нужные правки обычным языком.
Например: «Внеси правки по красным отметкам на скриншотах, проверь
мобильный вид и опубликуй на существующем сайте».
GPT читает актуальный main, меняет файлы site/, проверяет их,
сохраняет в main и проверяет GitHub Actions / живую публикацию.
Если получился pull request, до его применения в main сайт не обновится.
В GitHub: Merge pull request → Confirm merge.
Обновляйте сайт после завершения публикации; GitVerse может выдавать
предыдущие файлы несколько минут после загрузки.
Не редактируйте одновременно один и тот же участок из двух GPT.
Новая беседа должна прочитать текущий репозиторий, а не опираться
только на старую переписку. AGENTS.md хранит инструкции прямо в проекте.

ЕСЛИ WORK В ЕЁ ИНТЕРФЕЙСЕ ПОКА НЕТ
Используйте доступный Codex Cloud:
на вебе Work in → Cloud → Select environment → Create environment,
выберите этот репозиторий → Get started → проверьте подготовку →
Publish → после Environment published нажмите Start a new task.
Первую настройку окружения выполняют на вебе или в desktop-приложении.
Обычный чат, имеющий только чтение GitHub, не подтверждает возможность
редактировать и публиковать; проверка выше выявит это ограничение.
