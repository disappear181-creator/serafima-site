Сайт и файлы уже подготовлены. Код писать, архив распаковывать и HTML
загружать вручную не нужно, если после шага 1 ChatGPT видит репозиторий

СЕЙЧАС: ОДИН ПЕРВЫЙ ШАГ
1. Откройте https://github.com/new?name=serafima-site&visibility=public&owner=@me
   под уже подключённым аккаунтом Антона disappear181-creator.
   Включите Add README / Add a README file, нажмите Create repository.
   В подключении GitHub к ChatGPT проверьте, что этот новый репозиторий
   разрешён. Если выбран режим All repositories, отдельный выбор не нужен.
   Пришлите сюда ссылку созданного репозитория.

ПОСЛЕ ЭТОГО АГЕНТ
Проверяет доступ на запись и ветку; загружает сайт, инструкцию AGENTS.md
и автопубликацию. Если новая ветка не main, адаптирует конфигурацию.
Все дальнейшие шаги выполняются по актуальному экрану, без догадок.

ОДНОРАЗОВОЕ ПОДКЛЮЧЕНИЕ ХОСТИНГА
2. Создайте аккаунт GitVerse https://gitverse.ru/ для владельца сайта,
   лучше Серафимы. Попробуйте логин serafima-demina. Если он занят,
   serafima-demina-psychologist. Логин не должен содержать точку.
   Это будет основа бесплатного адреса <логин>.gitverse.site.
   Ничего создавать в разделе репозиториев вручную не нужно:
   подготовленный bootstrap сделает это после подключения токена.

3. В GitVerse: аватар пользователя → Настройки → Управление токенами.
   Создайте токен для этой публикации. Необходимые права:
   Пользователь — Чтение; Репозиторий — Чтение и Запись.
   Скопируйте токен в GitHub вашего сайта:
   Settings → Secrets and variables → Actions → Repository secrets →
   New repository secret.
   Name: GITVERSE_TOKEN
   Secret: скопированный токен
   Нажмите Add secret. Пароли/токены в чат не присылайте.
   После сохранения сообщите агенту: «Токен сохранён».

АГЕНТ
Запускает и проверяет bootstrap и загрузку сайта. Успех этой загрузки
ещё не означает публикацию страницы. Агент сообщает точную ссылку
репозитория GitVerse и следующий экран настроек.

4. В этом репозитории GitVerse один раз включите:
   Настройки → Репозиторий → CI/CD → включить → Обновить.
   Настройки → Страницы → включить Pages → Источник: Ветка → main →
   Папка: / (корень) → Сохранить.
   Выбираем корень /, не /site: скрипт переносит файлы в корень хостинга.
   Никакой шаблон, Jekyll или редактор конструктора выбирать не нужно.
   Название GitHub workflow: Publish website to GitVerse.

ПРОВЕРКА ЗАПУСКА
Агент проверяет фактическую публикацию, живую страницу и кнопки записи.
Открытие из РФ подтверждается отдельно: откройте готовую ссылку через
домашний Wi-Fi и мобильную сеть без VPN. Агент не называет свою проверку
из облака российской проверкой. После успешной проверки принимаем запуск.

ПОДКЛЮЧЕНИЕ PLUS СЕРАФИМЫ
5. Серафима создаёт собственный GitHub-аккаунт, если его ещё нет.
   Антон в репозитории: Settings → Collaborators → Add people → выбрать
   точный GitHub-логин Серафимы. Она принимает приглашение. Учётные записи
   и пароли не делятся; предоставляется доступ только к проекту сайта.
   В её ChatGPT Plus на вебе подключите GitHub и разрешите serafima-site.

ПОСЛЕ ЗАПУСКА
Правки по скриншотам собираем заранее и применяем уже после проверки
живого внешнего сайта. Агент сам редактирует код, проверяет и публикует.
Коммит/PR отдельно от main не обновляет сайт: нужен push или merge в main.
Если интерфейс требует подтверждения merge, это короткое действие владельца;
не обещаем, что оно автоматически доступно во всех аккаунтах Plus.
Тест передачи можно сделать изменением комментария в config.js —
видимый сайт остаётся прежним, а публикация проверяется.

ВАЖНО ДЛЯ ВЫБОРА ХОСТИНГА
Адрес бесплатный, но принадлежит хостингу и изменится при переезде.
GitVerse Pages пока не поддерживает собственные домены.
Вопрос общего запрета коммерческой рекламы в условиях GitVerse и
разрешённых корпоративных Pages остаётся неуточнённым у провайдера.
Выбор как постоянной бизнес-площадки и доступ из разных сетей пока
не считаем принятыми только по факту готовности файлов.
