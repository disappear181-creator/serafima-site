# Сайт Серафимы Дёминой

Основной сайт: `site/`. Это обычные HTML, CSS и JavaScript. Сохраняйте согласованный дизайн и тексты при ограниченных правках. Не переводите проект на фреймворк без задачи, требующей этого.

- `site/index.html` — содержание и разделы.
- `site/style.css` — оформление и адаптивность.
- `site/config.js` — цены, контакты, фотографии, документы и режим согласования.
- `site/app.js` — меню, документы и ссылки на контакты для записи.
- `site/privacy.html` — описание обработки данных.
- `site/assets/` — локальные изображения и документы.

Сайт опубликован на https://serafima-demina.gitverse.site/. Владелец подтвердил, что сайт отображается, и поручил применить правки по скриншотам 1–8. Фотографии и дипломы пока не предоставлены. Не придумывайте квалификацию, контакты, цены, фотографии или юридические реквизиты. Режим согласования и `noindex` снимаются по запросу владельца после проверки содержания.

Форма записи удалена по поручению владельца 13 октября 2026 года. Для записи посетитель самостоятельно пишет в Telegram или WhatsApp, указывая имя и предпочтительный формат встречи — очно или онлайн. На сайте нет полей для контактов, автоматической отправки или подготовки черновика. Не восстанавливайте форму и не подключайте Telegram-бота без нового поручения. Описание в `site/privacy.html` должно соответствовать этой механике.

Все файлы оформления должны быть локальными, все пути — относительными. Не подключайте внешние шрифты/CDN без необходимости. Сайт должен переноситься копированием содержимого `site/` без сборки, подписки на конструктор или серверного OpenAI API.

После изменений проверьте синтаксис JS, ссылки на локальные файлы, меню, кнопки записи и мобильный вид при наличии браузерного инструмента. Сообщайте, если браузерная проверка недоступна.

Публикация: изменение `main` запускает `.github/workflows/publish-gitverse.yml`. Bootstrap получает логин GitVerse из токена и создаёт выделенный публичный репозиторий с тем же именем, если его ещё нет. Затем скрипт отправляет файлы сайта в этот репозиторий; там Pages публикует их. Нужен только секрет `GITVERSE_TOKEN` в GitHub Actions Secrets: Пользователь — Чтение, Репозиторий — Чтение и Запись. Нельзя перезаписывать чужой существующий репозиторий без проверки принадлежности этому сайту. CI/CD и Pages владелец один раз включает через интерфейс: их включение через API не подтверждено. Не просите присылать токен в чат, не сохраняйте его в коде и не печатайте.

Коммит или успешный git push — ещё не подтверждение доступности опубликованного сайта. Проверяйте сначала GitHub Actions, затем GitVerse Pages и живую страницу, когда доступны соответствующие инструменты. Не заявляйте о проверке из РФ, если не было реального российского подключения.

## Редактирование из двух аккаунтов ChatGPT

Антон хранит исходники на своём GitHub; Серафима владеет GitVerse и сайтом. Она может редактировать этот же проект из своего ChatGPT после предоставления GitHub collaborator access и отдельного подключения GitHub в её аккаунте. Актуальная инструкция — START_HERE.txt. Не переносите сайт и не создавайте новый репозиторий ради второго редактора.

Перед изменениями читайте текущие main и AGENTS.md. Сохраняйте чужие новые изменения; при конфликте свежей ветки перечитайте её и примените только свой патч. Для публикации изменения должны попасть в main: отдельный pull request сам по себе не обновляет сайт. Используйте настроенные GitHub Actions и GITVERSE_TOKEN, не просите Серафиму передавать секрет хостинга в GPT.

Подключение аккаунта Серафимы проверено 12 октября 2026 года: служебный комментарий сохранён в main, публикация и Verify public website завершились успешно. Повторять проверку комментария для обычных правок не требуется. Пользователь описывает правки обычными словами и скриншотами; техническую подготовку, изменения, проверки и публикацию выполняйте самостоятельно в доступных инструментах.

При работе над проектом открывать актуальную версию этого же файла и дополнять её. Для сохранения использовать замену по тому же Library ID с проверкой текущей версии, когда она доступна. Каждое доступное сообщение пользователя и ассистента, включая промежуточные обновления и итог, каждое решение, изменение, коммит и результат проверки записывать отдельным событием с новым неизменяемым номером V. Сохранять полный текст сообщения, проект, дату, автора, связанный патч, статус и доказательство результата. Не придумывать неизвестные время, проверки или публикации. Номер V отражает порядок внесения в журнал; версия кода определяется SHA коммита. Не журналировать секреты, скрытые рассуждения, служебные метаданные или полный технический вывод инструментов. Исправления истории оформлять новой записью.

Патч заранее продумывать как завершённый результат: конкретное требование, полный набор зависимых правок, подходящие проверки, коммит и проверяемый итог. Для изменения сайта после попадания в main дождаться GitHub Actions и успешного Verify public website. Для правки только документации или журнала публикация сайта не требуется; указать это явно. Не отмечать патч завершённым только по факту записи кода или git push.

Колонка «Готовность» вычисляется из статуса, проверок, публикации и доказательства. При добавлении события расширять существующую таблицу, переносить формулу этой колонки, форматы и проверки данных. Счётчики учитывают строки до 10000; при приближении к этой границе расширить диапазоны. После обновления пересчитать, проверить новые записи и сохранить тот же файл. Не создавать фиктивных проверок или сохранять тестовые строки.

Доводить всю разрешённую работу до результата. Отменённую владельцем работу явно закрывать с причиной. При реальном ограничении фиксировать, что сделано, конкретную причину остановки и один следующий шаг владельца. Не оставлять неописанные задачи или обещания без статуса. Перед итоговым ответом сохранить сообщения текущего рабочего цикла и запись итогового ответа в этом же журнале, затем отправить зафиксированный ответ. Фоновый сбор сообщений из других чатов не подключён; этот порядок выполняется агентом при доступе к проекту и каноническому файлу. Если журнал недоступен, сообщить о невозможности записи и не создавать дубликат.
